# RAG Chatbot — Groq + BM25 + React (Python 3.13 ready)

A simple, beginner-friendly Retrieval-Augmented Generation (RAG) chatbot.
Upload PDF / text files, then ask questions. Answers are generated by
**Groq** (free tier — fast Llama 3.3) and grounded in your uploaded
documents using **BM25 keyword retrieval** (no embedding API needed).

## Stack (no native deps, no compiling, ~80 MB total install)

| Layer       | Technology                                                              |
| ----------- | ----------------------------------------------------------------------- |
| Frontend    | React 18 + Vite                                                         |
| Backend     | FastAPI (Python **3.13**)                                               |
| Retrieval   | **BM25** via [`rank-bm25`](https://pypi.org/project/rank-bm25/) — pure Python, local, offline |
| LLM         | Groq `llama-3.3-70b-versatile` via the OpenAI-compatible API             |

> **Why BM25 instead of embeddings?** Groq's API has chat completions but
> **no embedding endpoint**. Rather than add a third API for embeddings,
> this build uses BM25 — the classic keyword-ranking algorithm behind
> Elasticsearch and Lucene. It works fully offline, is extremely fast,
> and is a perfectly valid form of RAG retrieval.

## Setup — exact commands

### Prerequisites

- **Python 3.13** — verify: `python --version`
- **Node.js 18+** — [nodejs.org](https://nodejs.org/)
- A **Groq API key** (free) — [console.groq.com/keys](https://console.groq.com/keys)

### 1. Backend

Open **PowerShell** in the project root:

```powershell
cd d:\rag_chatbot\backend

# Activate your existing venv (created earlier)
.\.venv\Scripts\Activate.ps1

# Install the one new dep — rank-bm25 — and refresh the rest
pip install --default-timeout=300 --only-binary :all: -r requirements.txt

# Start the backend (uses GROQ_API_KEY from .env)
python main.py
```

Backend is now at **http://localhost:8000**. Visit
**http://localhost:8000/health** to confirm `"groq_key_configured": true`.

> **Starting from scratch?** Delete `backend\.venv` and recreate:
> ```powershell
> cd d:\rag_chatbot\backend
> python -m venv .venv
> .\.venv\Scripts\Activate.ps1
> python -m pip install --upgrade pip
> pip install --default-timeout=300 --only-binary :all: -r requirements.txt
> copy .env.example .env
> # edit .env — paste your GROQ_API_KEY
> python main.py
> ```

### 2. Frontend (in a second PowerShell window)

```powershell
cd d:\rag_chatbot\frontend
npm install      # first time only
npm run dev
```

Open **http://localhost:5173**.

## How to Use

1. Click **+ Upload PDF / TXT** in the sidebar.
2. Pick a file (try `backend/sample_data/sample.txt`).
3. Wait a second — text is chunked, tokenized, and indexed locally.
4. Type a question, e.g. *"What are the gas giants?"*
5. Groq's Llama 3.3 answers using only the retrieved context, citing source filenames.

Click the **×** next to a file to remove it from the index.

## API Endpoints

The backend exposes a small JSON API. The frontend talks to it via the
`/api/*` proxy in `vite.config.js`.

| Method   | Path                | Description                                                  |
| -------- | ------------------- | ------------------------------------------------------------ |
| `GET`    | `/`                 | Service info (model, retrieval method, key status)           |
| `GET`    | `/health`           | Index status: total chunks + source count                    |
| `POST`   | `/upload`           | Upload a file (`multipart/form-data`, field `file`). Allowed: `.pdf`, `.txt`, `.md` |
| `POST`   | `/chat`             | Ask a question. Body: `{ "question": "...", "history": [...] }` |
| `GET`    | `/sources`          | List indexed files and chunk counts                          |
| `DELETE` | `/sources/{name}`   | Remove a file (deletes chunks + the saved file)              |

### Example: ask a question

```powershell
curl.exe -X POST http://localhost:8000/chat `
  -H "Content-Type: application/json" `
  -d "{\"question\": \"What are the gas giants?\", \"history\": []}"
```

Response:

```json
{
  "answer": "The gas giants are Jupiter and Saturn... (sample.txt)",
  "sources": ["sample.txt"],
  "retrieved_chunks": 3,
  "usage": {
    "prompt_tokens": 412,
    "completion_tokens": 87,
    "total_tokens": 499
  }
}
```

## How It Works (the RAG flow)

```
[Upload]  PDF / TXT
   │
   ▼
[document_processor.py]  extract text → split into ~800-word chunks
   │
   ▼
[vector_store.py]  tokenize each chunk (lowercase, alphanumerics) →
                   append to corpus.json → rebuild BM25 index in memory
   │
[Query]  user question
   │
   ▼
[vector_store.py]  tokenize query → BM25.get_scores() → top-K
   │
   ▼
[rag_engine.py]   build prompt with <context> blocks + question
                  call Groq llama-3.3-70b-versatile via OpenAI SDK
                  (Groq is OpenAI-compatible — same client, different base_url)
   │
   ▼
[Response]  answer + cited sources
```

## Local Storage

Everything stays on your machine. The Groq API only sees the question
plus the retrieved context — never the full document set.

| Path                              | What's there                                          |
| --------------------------------- | ----------------------------------------------------- |
| `backend/uploads/`                | Original files you uploaded                           |
| `backend/vector_db/corpus.json`   | List of `{source, chunk_index, text, tokens}`         |
| `backend/sample_data/`            | Example file + JSON snapshot of stored chunk shape    |

To wipe the index, delete `backend/vector_db/corpus.json` and restart.

## Configuration

All knobs live in `backend/.env` (copy from `.env.example`):

| Variable           | Default                                  | Purpose                                                              |
| ------------------ | ---------------------------------------- | -------------------------------------------------------------------- |
| `GROQ_API_KEY`     | —                                        | Required. Get one at https://console.groq.com/keys                   |
| `GROQ_MODEL`       | `llama-3.3-70b-versatile`                | Try `llama-3.1-8b-instant` for faster / cheaper, `gemma2-9b-it` for an alternative |
| `GROQ_BASE_URL`    | `https://api.groq.com/openai/v1`         | Don't change unless Groq changes their endpoint                      |
| `VECTOR_DB_DIR`    | `./vector_db`                            | Where the BM25 corpus lives                                          |
| `CHUNK_SIZE`       | `800`                                    | Words per chunk                                                      |
| `CHUNK_OVERLAP`    | `100`                                    | Words shared between adjacent chunks                                 |
| `TOP_K`            | `4`                                      | Number of chunks retrieved per question                              |

## Troubleshooting

**`/health` shows `"groq_key_configured": false`** — your `.env` isn't being
read. Check that `backend\.env` exists and contains `GROQ_API_KEY=gsk_...`
(no quotes, no spaces around `=`), then restart `python main.py`.

**`401 Unauthorized` from Groq** — the key in `.env` is wrong or revoked.
Get a fresh one at https://console.groq.com/keys.

**`model_not_found` from Groq** — the value of `GROQ_MODEL` isn't a model
your Groq account can use. Run `curl https://api.groq.com/openai/v1/models -H "Authorization: Bearer $env:GROQ_API_KEY"`
to list available models, or pick from
https://console.groq.com/docs/models.

**`pip install rank-bm25` is slow** — it's pure Python, < 100 KB. Slow
install means network. Add `--default-timeout=600 --retries 10`.

**No answer / "I don't have enough information"** — confirm your file
appears in the sidebar and that text was extracted. Some scanned PDFs are
images and need OCR (out of scope here). Try rephrasing the question to
include keywords that actually appear in the document — BM25 is a keyword
matcher, so wording matters more than with embeddings.

**Want to start over from scratch** — delete `backend/.venv`,
`backend/vector_db/*`, and `backend/uploads/*`, then re-run setup.
